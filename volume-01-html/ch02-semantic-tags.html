Introduction

In software engineering, the architecture of your application dictates how easily it can be understood, maintained, and scaled. Early web development relied heavily on generic containers to build layouts, resulting in code that was visually functional but structurally meaningless to machines—a phenomenon known as "Div Soup."

Modern HTML5 introduced a clear distinction between Semantic Landmarks (tags that explicitly describe their purpose) and Generic Containers (tags used purely for layout). Furthermore, to bridge the gap between our HTML structure and our CSS styling, we must use Identifiers to label these elements.

In this chapter, you will learn how to architect a page using meaningful landmarks, when to fall back on generic containers like <div> and <span>, and how to classify your elements using class and id attributes.

Key Concepts

Category Elements / Attributes Engineering Purpose
Semantic Landmarks <header>, <main>, <footer>, <nav> Defines major, meaningful regions of a webpage for browsers, SEO, and assistive technologies.
Thematic Groupings <section>, <article>, <aside> Organizes related content within the main landmarks into logical, self-contained units.
Generic Containers <div> (Block), <span> (Inline) Provides structure for CSS layouts and styling when no semantic meaning applies.
Identifiers class, id Global attributes used to label elements, creating the necessary hooks for CSS and JavaScript.

1. Semantic Landmarks (The Big Picture)

Landmarks are the primary structural boundaries of your page. They provide a high-level map that screen readers and search engine crawlers use to navigate your application.

The <header>

The <header> element represents introductory content. While typically used at the very top of a page for logos and global search bars, it can also be used inside an <article> to group a title and author name.

The <main>

The <main> element is the "Source of Truth" for your page. It contains the unique, dominant content of the document. Strict Rule: There must only be one visible <main> element per page. This is critical for accessibility.

The <footer>

The <footer> represents the closing metadata of a section or page. It typically contains copyright data, legal links, or version numbers (like our 041820261802 version tag).

The <nav>

The <nav> (Navigation) element is reserved for major blocks of navigation links. Not every group of links needs a <nav> tag—save it for primary site menus or tables of contents.

<!-- Example of a Semantic Landmark Architecture --> <header> <h1>Allegro Yield Dashboard</h1> <nav> <a href="/reports">Reports</a> <a href="/settings">Settings</a> </nav> </header> <main> <!-- Primary content goes here --> </main> <footer> <p>Internal Use Only. Version 2.4.1</p> </footer>

2. Generic Containers: Div and Span

If semantic tags are so important, why do we ever use generic containers? The answer is Layout and Styling. Sometimes you need to wrap three elements together simply to apply a CSS Grid layout. That wrapper has no thematic meaning—it is purely mechanical. For these scenarios, we use <div> and <span>.

The <div> (Division)

The <div> is a block-level element. It is the primary "box" used in web layouts. Because it is block-level, it naturally starts on a new line and expands to fill the width of its parent.

<!-- Using a div to group buttons for layout --> <div class="button-group"> <button>Submit</button> <button>Cancel</button> </div>

The <span>

The <span> is an inline-level element. It is used to wrap a small fragment of text inside a block element without breaking the flow of the text to a new line.

<!-- Using a span to target a single word for CSS --> <p> The server status is <span class="status-green">OPERATIONAL</span>. </p>

3. Element Identity: Class vs. ID

A generic <div> is useless to CSS unless we can identify it. We do this using Global Attributes. The two most important identifiers are class and id.

The Class Attribute (Categories)

A class is used to categorize elements. You can use the exact same class name on dozens of elements across your page. An element can also have multiple classes separated by a space.

<!-- Multiple elements sharing the 'card' category --> <article class="card highlight">Content A</article> <article class="card">Content B</article>

The ID Attribute (Unique Entities)

An id is a unique identifier. An ID name can only be used once per HTML document. IDs are heavily used as hooks for JavaScript logic and internal anchor links.

<!-- A unique identifier for the main chart --> <section id="primary-yield-chart">...</section>
🛠️ Technical Standard: Naming Conventions

Professional software engineers use kebab-case for naming classes and IDs. All letters are lowercase, and words are separated by hyphens (e.g., main-nav-container).

4. Architecture Refactoring Comparison

Compare the code below. The "Div Soup" version relies entirely on classes to explain its structure. The "Engineered" version uses Semantic Landmarks, reserving classes purely for styling.

<!-- ❌ DIV SOUP (Poor Architecture) --> <div class="header"> <div class="nav">...</div> </div> <div class="main-content">...</div> <!-- ✅ ENGINEERED (Semantic & Labeled) --> <header class="site-header"> <nav id="global-nav">...</nav> </header> <main class="dashboard-layout">...</main>

📋 Chapter Summary

  • Use Landmarks (<header>, <main>, <footer>, <nav>) to define the high-level map of your page.
  • Only use one <main> tag per HTML document.
  • Use Generic Containers (<div>, <span>) only for CSS layout/styling without adding semantic meaning.
  • Use the class attribute to group multiple elements into styling categories.
  • Use the id attribute for unique, one-of-a-kind elements.
  • Always write class and ID names in kebab-case.
