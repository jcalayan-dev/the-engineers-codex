Introduction

Text is the most fundamental type of content on the web. Before images, videos, or animations existed online, there was text. HTML provides a rich set of elements to structure and format text so that it is readable, accessible, and meaningful to both humans and search engines.

In this chapter, you will learn how to use headings to create a clear hierarchy, paragraphs for body content, and inline formatting elements to emphasize or highlight specific words. You will also understand the critical difference between block-level and inline elements — a concept that will directly impact how your pages are laid out.

💡 Engineering Note

HTML text elements are not just about making things "look" bold or italic. They carry semantic meaning. For example, screen readers for visually impaired users rely on heading levels to navigate a page. Using the right tag is an accessibility requirement, not just a design choice.

Key Concepts

Element Type Purpose
<h1> – <h6> Block Headings. <h1> is the most important (page title), <h6> is the least.
<p> Block Paragraph. Used for body text. Browsers add spacing above and below automatically.
<strong> Inline Strong importance. Displayed as bold. Screen readers emphasize this text.
<em> Inline Emphasis. Displayed as italic. Conveys stress or a different tone.
&entity_name; Inline HTML Entities. Used to display reserved characters (like <) and special symbols safely.
<br> Inline Line break. Forces text to the next line without starting a new paragraph.
<hr> Block Horizontal rule. Creates a visible divider line between sections.
<span> Inline A generic inline container. Has no visual effect by itself — used for CSS styling hooks.
<blockquote> Block Indicates a quotation from another source. Browsers typically indent it.
<code> Inline Represents a fragment of computer code. Displayed in a monospace font.
<pre> Block Preformatted text. Preserves whitespace and line breaks exactly as written.

Headings: The Hierarchy of Content

HTML provides six levels of headings. Think of them like an outline for a research paper or a book's chapter structure. You should only use one <h1> per page (the main title), then use <h2> through <h6> for sub-sections.

<!-- Heading hierarchy example --> <h1>The Engineer's Codex</h1> <h2>Volume I: HTML Essentials</h2> <h3>Chapter 3: Text and Typography</h3> <h4>Section: Headings</h4> <h5>Sub-section: Best Practices</h5> <h6>Minor Detail</h6>
⚠️ Common Mistake

Never skip heading levels just for styling purposes. For example, do not jump from <h2> to <h5> because you want smaller text. Use CSS for visual sizing — use HTML headings for logical structure.

Paragraphs and Body Text

The <p> tag is the most common element on the web. It wraps a block of text and tells the browser to add vertical spacing before and after it. Paragraphs are block-level elements, meaning they always start on a new line and take up the full available width.

<p>This is the first paragraph. It stands alone as a block.</p> <p>This is the second paragraph. Notice the automatic spacing between them.</p>

Inline Formatting: Bold, Italic, and More

Inline elements live inside block elements like paragraphs. They do not start a new line — instead, they flow within the text. Here are the most important ones:

<p> This word is <strong>very important</strong>. This word has <em>emphasis</em>. This is <code>inline code</code>. </p>
Tag Visual Result Semantic Meaning
<strong> Bold text Strong importance (meaningful to screen readers)
<b> Bold text Visually bold only (no semantic meaning)
<em> Italic text Stressed emphasis (meaningful to screen readers)
<i> Italic text Visually italic only (no semantic meaning)
<mark> Highlighted text Text marked for reference or relevance
<small> Smaller text Side comments or fine print
<del> Strikethrough Content that has been deleted or is no longer accurate
<sub> H2O Subscript (chemical formulas, footnotes)
<sup> x2 Superscript (exponents, ordinals like 1st)

Block vs Inline: The Core Difference

Understanding whether an element is block-level or inline is one of the most important concepts in HTML and CSS. It determines how elements stack and flow on the page.

Property Block Elements Inline Elements
Starts on a new line? Yes — always No — flows within the line
Takes full width? Yes — stretches to fill the container No — only as wide as its content
Can contain other blocks? Yes No — only text and other inline elements
Examples <p>, <h1>, <div>, <blockquote> <strong>, <em>, <span>, <a>
<!-- Block vs Inline behavior --> <!-- These two paragraphs stack vertically (block) --> <p>First paragraph.</p> <p>Second paragraph.</p> <!-- These two spans sit side by side (inline) --> <p> <span>Hello</span> <span>World</span> </p>

Special Text Elements

HTML also provides elements for specific text patterns that go beyond simple bold and italic:

<!-- Blockquote for citations --> <blockquote> <p>The best way to predict the future is to invent it.</p> <footer>— Alan Kay</footer> </blockquote> <!-- Preformatted text preserves spaces and line breaks --> <pre> Line 1 Line 2 Indented line </pre> <!-- Abbreviations with tooltip --> <p>The <abbr title="HyperText Markup Language">HTML</abbr> spec is maintained by W3C.</p>

Special Characters: HTML Entities

In HTML, certain characters are reserved because the browser uses them as part of the language itself. For example, < and > mark the start and end of tags. If you type them directly into your content, the browser will try to interpret them as code instead of displaying them as text.

To safely display these characters, we use HTML Entities. An entity always follows this syntax: an ampersand (&), followed by the entity name, followed by a semicolon (;).

Character Entity Code Technical Use Case
<&lt;Less Than — displaying HTML tags in documentation.
>&gt;Greater Than — closing bracket for tag display.
&&amp;Ampersand — must be escaped to avoid triggering an entity.
©&copy;Copyright symbol — used in footer metadata.
°&deg;Degree symbol — used for temperature (e.g., 25°C).
 &nbsp;Non-breaking space — prevents words from splitting across lines.
"&quot;Double quote — used inside attribute values.
<!-- Displaying a tag as text using entities --> <p>To bold text, use the <code>&lt;strong&gt;</code> tag.</p> <!-- Engineering example: Temperature --> <p>Operating Range: -40&deg;C to +125&deg;C.</p> <!-- Copyright in a footer --> <p>&copy; 2026 The Engineer's Codex</p>
💡 Named vs. Numeric Entities

Every entity can also be written using a numeric code. For example, &lt; can also be written as &#60;. Named entities are preferred because they are easier to read and remember.

Line Breaks and Horizontal Rules

Sometimes you need to force a line break without creating a new paragraph, or add a visual divider between sections. HTML provides two self-closing elements for this:

<!-- Line break (no closing tag needed) --> <p> 123 Main Street<br> Springfield, IL 62704<br> United States </p> <!-- Horizontal rule — a visual section divider --> <hr>
💡 Best Practice

Avoid using <br> for spacing between elements. That is what CSS margins and padding are for (covered in Volume II). Use <br> only where a line break is part of the content itself, such as addresses or poetry.

📋 Chapter Summary

  • Use <h1> through <h6> for a clear content hierarchy — never skip levels.
  • Wrap body text in <p> tags — they are the workhorses of content.
  • Use <strong> and <em> for meaningful emphasis, not <b> and <i>.
  • Block elements stack vertically; inline elements flow within the line.
  • Use <blockquote> for quotes, <code> for code, <pre> for preserving whitespace.
  • Use <br> only for content-based line breaks, not for visual spacing.
  • Use HTML Entities (like &lt; and &copy;) to safely display reserved characters and technical symbols.
