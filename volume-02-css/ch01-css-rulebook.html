Introduction

If HTML is the structure of our application, CSS (Cascading Style Sheets) is the engine that drives the visual presentation. Unlike HTML, which is a markup language used for description, CSS is a rule-based language. You define groups of styles that should be applied to specific elements or groups of elements on your web page.

In this chapter, we will break down the anatomy of a CSS rule set, explore how to target elements using selectors, and understand the "Cascading" logic that determines which rules win when multiple styles conflict. Mastering these mechanics is the first step toward visual engineering.

Key Concepts

Term Definition Analogy
Selector The "Target". Tells the browser which HTML element to style. The address on an envelope.
Declaration A single setting consisting of a Property and a Value. An instruction (e.g., "Paint the door red").
The Cascade The logic used to resolve conflicts when multiple rules apply to one element. A hierarchy of command.
Specificity A weight assigned to a selector that determines its "importance" over others. A rank or priority level.

1. Anatomy of a CSS Rule Set

A CSS rule set consists of a Selector followed by a Declaration Block wrapped in curly braces {}. Each declaration inside the block must end with a semicolon ;.

/* Selector */ h1 { color: white; /* Property: Value; */ font-size: 24px; /* Declaration */ }

2. Targeting Elements: Common Selectors

To apply styles, you must first "select" the element. As a Senior Engineer, you should use the most efficient selector for the job to keep your code clean.

  • Element Selector: Targets all instances of a specific HTML tag (e.g., p, h1).
  • Class Selector: Targets elements with a specific class attribute. Indicated by a dot (.).
  • ID Selector: Targets a single unique element. Indicated by a hash (#).
/* Targets all paragraphs */ p { line-height: 1.6; } /* Targets any element with class="btn" */ .btn { background-color: blue; } /* Targets the unique element with id="main-nav" */ #main-nav { border-bottom: 1px solid black; }

3. The "Cascading" Logic

The "C" in CSS stands for Cascading. This means the order of rules matters. If two rules have the same "weight," the one written last in the stylesheet will be the one the browser follows.

💡 Engineering Principle: Source Order

Always place your most general styles (like global resets) at the top of your CSS file and your most specific styles (like unique page sections) at the bottom. This allows the cascade to work for you, not against you.

4. Specificity: The Priority System

When different selectors target the same element, the browser uses Specificity to decide which rule wins. Specificity is calculated as a score:

Selector Type Priority Level Example
Inline StylesHighest (1000)style="..."
IDsHigh (100)#header
Classes / AttributesMedium (10).active
ElementsLow (1)h1
/* This rule has a specificity of 1 (Element) */ p { color: red; } /* This rule has a specificity of 10 (Class) and WINS */ .main-text { color: blue; }

📋 Chapter Summary

  • A Rule Set includes a Selector and a Declaration Block.
  • Use Selectors to target HTML elements by tag, class, or ID.
  • The Cascade ensures that if weights are equal, the last rule written wins.
  • Specificity acts as a tie-breaker, giving priority to IDs over Classes, and Classes over Elements.
  • Professional engineers favor Classes for reusable styling and reserve IDs for unique components.
